# 🔍 Ghost 文章创建流程完整追踪

本文档详细追踪了 Ghost CMS 中创建一篇文章的完整流程，从 HTTP 请求到数据库持久化的每一个环节。

---

## 📊 流程概览

```
HTTP POST Request
    ↓
1. Web Layer (路由与中间件)
    ↓
2. API Layer (端点处理器)
    ↓
3. Service Layer (业务逻辑，可选)
    ↓
4. Model Layer (数据模型与 ORM)
    ↓
5. Database (MySQL/SQLite)
    ↓
Response (201 Created)
```

---

class PostsService {
    constructor({urlUtils, models, isSet, stats, emailService, postsExporter}) {
        this.models = models;                    // 行 22
        this.emailService = emailService;        // 行 25
        this.postEmailHandler = new PostEmailHandler({
            models,
            emailService

    // 编辑文章服务（示例）
    async editPost(frame, options) {
        // 1. 邮件发送前验证
        await this.postEmailHandler.validateBeforeSave(frame);  // 行 64

        // 2. 调用模型层编辑
        const model = await this.models.Post.edit(
            frame.data.posts[0],
            frame.options
        );                                       // 行 66

        // 3. 创建或重试邮件发送
        await this.postEmailHandler.createOrRetryEmail(model);  // 行 68

        // 4. 转换为 DTO
        const dto = model.toJSON(frame.options); // 行 70

        // 5. 触发事件处理器
        if (typeof options?.eventHandler === 'function') {
            await options.eventHandler(this.getChanges(model), dto);  // 行 73

        return dto;                              // 行 76
    }
}

#### 5.2 Post.add() 方法

**文件**: `ghost/core/core/server/models/post.js`

**位置**: 行 1340-1365

```javascript
add: function add(data, unfilteredOptions) {
    let options = this.filterOptions(unfilteredOptions, 'add', {extraAllowedProperties: ['id']});

    // 定义内部 addPost 函数
    const addPost = (() => {
        // 检查资源限制（文章数量限制）
        return limitService.errorIfWouldGoOverLimit('posts')
            .then(() => {
                // 调用父类（Bookshelf Model）的 add 方法
                return ghostBookshelf.Model.add.call(this, data, options);
            })
            .then((post) => {
                // 添加成功后，重新获取完整的文章数据
                // 包括所有关联关系和计算字段
                return this.findOne({
                    status: 'all',
                    id: post.id
                }, _.merge({transacting: options.transacting}, unfilteredOptions));
            });
    });

    // 如果没有事务，创建新事务
    if (!options.transacting) {
        return ghostBookshelf.transaction((transacting) => {
            options.transacting = transacting;
            return addPost();
        });
    }

    // 已有事务，直接执行
    return addPost();
}
```

**执行流程**:
1. **过滤选项** - `filterOptions()`
2. **检查限制** - `limitService.errorIfWouldGoOverLimit('posts')`
3. **调用基类** - `ghostBookshelf.Model.add()`
4. **重新获取** - `findOne()` 获取完整数据（包含关联）
5. **事务管理** - 自动创建或使用现有事务

#### 5.3 基类 Model.add()

**文件**: `ghost/core/core/server/models/base/index.js`

**位置**: 约行 200-300 (Bookshelf 扩展)

```javascript
// Bookshelf Model 基类扩展
const ghostBookshelf = Bookshelf.extend({
    Model: Bookshelf.Model.extend({
        // add 方法
        add: function add(data, options) {
            // 1. 应用默认值
            const defaults = this.defaults ? this.defaults() : {};
            data = _.defaults(data, defaults);

            // 2. 权限检查
            data = this.filterData(data);

            // 3. 验证数据
            this.validate(data, options);

            // 4. 触发 onCreating 钩子
            return this.triggerThen('creating', this, data, options)
                .then(() => {
                    // 5. 触发 onSaving 钩子
                    return this.triggerThen('saving', this, data, options);
                })
                .then(() => {
                    // 6. 执行数据库插入
                    return Bookshelf.Model.prototype.save.call(this, data, options);
                })
                .then((model) => {
                    // 7. 触发 onCreated 钩子
                    return this.triggerThen('created', model, options);
                })
                .then((model) => {
                    // 8. 触发 onSaved 钩子
                    return this.triggerThen('saved', model, options);
                })
                .then((model) => {
                    // 9. 触发领域事件
                    this.emitChange(model, 'added', options);
                    return model;
                });
        }
    })
});
```

**主要钩子**:

```javascript
// 创建前钩子 (onCreating)
onCreating: function onCreating(model, options) {
    // 1. 设置创建者
    if (!model.get('created_by')) {
        model.set('created_by', options.context.user);
    }

    // 2. 生成 slug
    if (!model.get('slug')) {
        return this.generateSlug(Post, model.get('title'), options)
            .then((slug) => {
                model.set('slug', slug);
            });
    }
},

// 保存前钩子 (onSaving)
onSaving: function onSaving(model, options) {
    // 1. 验证内容格式
    if (model.hasChanged('mobiledoc')) {
        this.validateMobiledoc(model.get('mobiledoc'));
    }

    // 2. 生成 HTML
    if (model.hasChanged('mobiledoc') || model.hasChanged('lexical')) {
        const html = this.generateHTML(model);
        model.set('html', html);

        // 3. 生成纯文本
        const plaintext = htmlToPlaintext(html);
        model.set('plaintext', plaintext);
    }

    // 4. URL 转换
    model.set('mobiledoc', urlUtils.mobiledocToTransformReady(model.get('mobiledoc')));

    // 5. 验证发布时间
    if (model.get('status') === 'scheduled') {
        this.validatePublishedAt(model);
    }
},

// 创建后钩子 (onCreated)
onCreated: function onCreated(model, options) {
    // 触发 post.added 事件
    model.emitChange('added', options);
},

// 保存后钩子 (onSaved)
onSaved: function onSaved(model, options) {
    // 1. 处理标签关联
    if (model.relations.tags) {
        return model.relations.tags.mapThen(...);
    }

    // 2. 处理作者关联
    if (model.relations.authors) {
        return model.relations.authors.mapThen(...);
    }
}
```

**钩子执行顺序**:
```
onCreating → onSaving → [数据库插入] → onCreated → onSaved → 触发领域事件
```

## 🔥 关键决策点

### 1. 为什么 add 跳过服务层？

**原因**:
- `add` 操作逻辑简单，不需要复杂业务协调
- 直接调用模型层更高效
- `edit` 和 `publish` 需要邮件处理，必须经过服务层

**对比**:
```javascript
// add: API → Model
api.posts.add → models.Post.add()

// edit: API → Service → Model
api.posts.edit → postsService.editPost() → models.Post.edit()
```

---

### 2. 为什么需要两次数据库查询？

**第一次**: 插入数据
```javascript
ghostBookshelf.Model.add.call(this, data, options)
```

**第二次**: 获取完整数据（包含关联）
```javascript
this.findOne({status: 'all', id: post.id}, unfilteredOptions)
```

**原因**:
- Knex `INSERT` 只返回插入的 ID
- 需要加载所有关联关系 (tags, authors, tiers)
- 需要获取计算字段和默认值
- 确保返回给客户端的数据完整

---

### 3. 事务管理策略

```javascript
if (!options.transacting) {
    return ghostBookshelf.transaction((transacting) => {
        options.transacting = transacting;
        return addPost();
    });
}
return addPost();
```

**策略**:
- **没有事务**: 自动创建新事务
- **已有事务**: 复用现有事务（批量操作）
- **保证原子性**: 主记录 + 关联记录要么全成功，要么全失败
